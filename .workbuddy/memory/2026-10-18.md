## 追加：前端性能/质量审查（同日晚些时候）

### 已实施（全部实测验证）
1. **NGL 懒加载（最大收益）**：`ngl` 原被 2 个组件静态 import → 打进入口 chunk，
   所有访客都要下 ~810KB 分子图形库。改为新建 `frontend/src/components/ngl.ts`
   的 `loadNgl()`（memoize + 失败不缓存），两个组件改 `import type` + 动态 import。
   实测入口 chunk **1659 KB → 370 KB（gzip 475 → 118 KB，-75%）**，ngl 单独 chunk
   1316 KB 仅在打开结构查看器时按需拉取。配套处理 unmount 竞态（`disposed` 标志，
   避免 loader 回来后对已销毁容器建 Stage）。
2. **轮询防重叠**：`JobsPage` / `JobDetailPage` / `HomePage` 的 `setInterval`
   改为「load 完成后再 setTimeout」的链式调度，慢响应不再叠加请求；
   `DesignSessionPage` 额外加 `inFlight` 守卫。
3. **`JobsPage` 自适应轮询**：有 queued/running 时 3s，全部终态后退到 15s
   （此前无论有没有在跑的任务都恒定 3s 打 API）。
4. **`DesignSessionPage` 串行 → 并行**：轮询里 `for` 循环逐个 `await api.getJob`
   改为 `Promise.all`，单轮耗时从 Σ(N) 降到 max(N)。

### 我犯的错（已回滚，记录以防重犯）
- **误判 `errors.${errorKey}` 为 bug**：我以为错误 key 在 `error.` 命名空间下、
  前端多加了 `errors.` 前缀，于是「修」成直接用 `errorKey`。
  **实际目录是 `errors: { "error.model_not_found": ... }` 这种扁平 quoted key**，
  i18next 完整路径就是 `errors.error.model_not_found`，**原代码是对的**。
- 定位方法错误：我先用手写 resolver 判断，结论不可信；后改用**真实 i18next
  库 + 真实 catalog** 实测才拿到确定结论（6/6 本地化正常）。
- 教训：**验证 i18n 行为必须用真库**，别手写 resolver；改之前先证明"现有行为有问题"。

### 前端审查方法（可复用）

### 第二轮：路由分包 + 轮询 hook 抽象

1. **路由级 code splitting**：`App.tsx` 原先把 6 个页面全静态 import（含 865 行的
   SettingsPage 与 DesignSessionPage）。改为 `React.lazy` + `Suspense`（fallback 用
   现有 `.spinner` 类），**HomePage 保持 eager** 保证首屏。
   实测入口 chunk **370 → 302 KB（gzip 118 → 103 KB）**，各页拆成 4–32 KB 独立 chunk。

   JobDetailPage/DesignSessionPage 五处的轮询调度统一。保证
   ① 上一轮 settle 后才排下一轮（不重叠）② unmount 后不再 setState ③ 抛错不中断轮询
   ④ `delayFor` 支持自适应节奏 ⑤ `enabled=false` 暂停。
   DesignSessionPage 里原本手写的 `inFlight` 守卫因此删除（hook 已覆盖）。
   JobsPage 用 `delayFor` 实现「有任务 3s / 全终态 15s」。

   **运行时验证方式（可复用）**：用项目自带 esbuild 把 hook 编译成 CJS，再用

   实测朴素版 max concurrent = 4，usePolling = 1，其余 4 项断言全通过。

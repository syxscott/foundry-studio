## foundry-studio 方向性转向：本地向导型 → Agent 优先控制面 + HPC 任务提交

用户明确否定「本地一键向导」思路（当前版面向不会配环境的小白，假设算力在本地）。
新方向三大支柱：
1. Agent 层 —— 专门 agent 灵活拼装模型环境，不手点表单卡配置；
2. 控制面 —— Agent 优先 Control API + 可控可视化 + 实验控制感（提交/盯进度/取消/回收）；
3. HPC 后端 —— 调用走超算任务提交制（model 在超算上，不用本地 worker）。

已与用户确认的设计决策（4 问）：
- 调度系统：尽量都兼容 → SchedulerBackend 抽象（slurm/pbs/lsf 可切换）
- 连接与传输：都兼容 → Transport 抽象（ssh+scp / 共享文件系统 / REST 网关）可插拔
- Agent 形态：两者都要 → API-first（外部 agent 经 Control API 驱动）+ 应用内对话式 agent，二者皆产出同一 JobSpec
- 超算调用 foundry 方式：还没定 → JobSpec.invocation 模板化（container/module/conda 占位），待集群细节再填

复用：四语 i18n、NGL 3D 查看器、SQLite 任务表（天然任务队列）。
替换：本地 worker/引擎层 → HPC Adapter（submit/poll/fetch）。
新增：Agent 层（对话 + Control API）。

落地 phase：A 后端解耦（JobSpec/SchedulerBackend/Transport + mock HPC 后端，本地先跑）；B Agent 层（Control API + 应用内聊天）；C 真实 HPC 后端（slurm/ssh 等插拔）；D UI 控制面 + agent 面板；E 外部 agent API 文档。
